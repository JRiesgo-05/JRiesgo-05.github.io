Astro content collections, explained with Django

The prompt

Explain Astro's content collections in terms of Django models and templates, as a one-page HTML artifact. Keep the text under five sentences, and show where the comparison breaks.

In five sentences

A collection is a Django model: its schema declares the fields.

Each Markdown file is a row; its frontmatter holds the values.

getCollection() is objects.all(), and its callback is .filter().

An .astro page is a view and a template in one file.

It breaks at time: Django works per request, Astro once at build.

4 · What that costs you

Three things Django has that Astro doesn't

No writes

There's no .save(). To add a post, you add a file and rebuild.

No migrations or admin

Change the schema and every existing file has to match it by hand.

One bad file stops the deploy

Validation runs at build, not on save. A typo in one post fails the whole site, which is annoying and also the point.
