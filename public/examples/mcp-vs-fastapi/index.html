MCP, explained with FastAPI

The prompt

Explain MCP in terms of FastAPI routes and Pydantic models, as a one-page HTML artifact. Keep the text under five sentences, and show where the comparison breaks.

In five sentences

An MCP server is a FastAPI app whose client is a model, not a browser.

A tool is a route: a name, a docstring and typed inputs that become a JSON schema.

A resource is a GET endpoint: data to read, nothing runs.

tools/list is /openapi.json: the menu the client reads first.

It breaks at who calls: your code picks the route, the model picks the tool.

	4 · What that costs you
	
Three things FastAPI never made you think about

	

		

			
			
Descriptions are code

			
In FastAPI a docstring is documentation. In MCP it's how the model routes. Rewording one changes which tool gets called.

		

		

			
			
Every tool costs context

			
An unused route costs nothing. An unused tool's name, description and schema sit in the model's context window on every turn.

		

		

			
			
Output becomes input

			
A FastAPI response goes to code that parses it. A tool result goes straight into the prompt, so text inside it can try to steer the model.
