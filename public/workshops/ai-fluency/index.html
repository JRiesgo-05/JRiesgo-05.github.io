2 · What is generative AI?

Stable

A very good text predictor

Generative AI runs on an LLM — a Large Language Model. Your phone guessing the next word in a message is the same trick, at an absurd scale.

Large means it was trained on roughly everything scrapeable, up to a cutoff date. Past that date it knows nothing — which is why it says so, and why coding assistants had to solve that problem.

2.1 · What is a token?

Stable

Story points, but for a model

You size your week in tickets and story points. A model sizes its work in tokens.

A tokenizer is what does the splitting — text into numbered pieces, roughly a word, often part of one. If I say a ticket is 5 points, it is 5 points. Same deal: deprioritised is four tokens, and it is four every time.

2.1.1 · Vector embeddings

Stable

Numbers with no meaning — until this step

A token ID is an index, nothing more. king is 13793 and truck is 13790 — three apart, and unrelated.

The embedding fixes that. Every token becomes a list of numbers — 1,024 of them in a typical model — positioning it in a space where distance is similarity.

This is what semantic search runs on. Ask for decks about retention and it finds the one that says churn.

2.2 · What is a context window?

Stable

One session, one budget

The context window is the total tokens a model can hold in a single conversation. Input and output both count against it — which is also how the labs price you, per input token and per output token.

Overload a person and they make mistakes. Give them five topics in one meeting and they derail. Models do exactly this: manage the window badly and the work derails, then degrades.

2.2.1 · Context drift

Stable

It doesn’t forget. It stops noticing.

A full window doesn’t error, and nothing gets deleted. But every token is weighed against every other one, so the more you load, the thinner the attention spreads. Anthropic calls it context rot: tokens up, recall down.

What you see is an agent that quietly stops honouring what you set at the start — and starts guessing instead of checking.

    3.3.1 · “One-shot”, the other meaning

    Shaky

    Same word. Different axis.

    Everything we just did counts examples in your prompt — zero, one, a handful.

    When an engineer says “Claude one-shotted it” they mean something else entirely: it got there on the first attempt. No examples involved.

    One counts what goes in. The other counts how many rounds it took.

    one-shot two meanings, two axes

    in prompting — examples you supply

    • zero-shotnone
    • one-shotone
    • few-shota handful

    in a coding agent — turns it took you

    • “one-shotted it”right, first attempt
    • “took me three”three corrections

    Do not chase the one-shotnine minutes perfecting a prompt to save a twenty-second follow-up is not a saving

    3.4 · Do we still need it?

    Stable

    Sometimes. The techniques are fading — the underlying skill is not.

    3.5 · Limitation of LLMs

    Confidently wrong is the default failure

    A model is excellent inside what it was trained on, and invents outside it. That inventing has a name you will hear all day: hallucination — an answer that is wrong and completely self-assured.

    3.6 · The other limitation

    Stable

    It cannot do arithmetic either

    A text predictor predicts plausible digits. Ask for 4,871 × 293 and you get a number of roughly the right size with the wrong digits in the middle — delivered with the same confidence as everything else.

    You cannot prompt your way out of this one. The fix is not a better question. It is letting the model stop guessing and run the calculation.

    4 · Tools

    Stable

    The LLM is the brain. Tools are the hands.

    A tool is code the model can ask to have run. It does not run it — it requests it, something else executes, and the result returns to its context.

    You never name the tool. You ask in plain English and the model infers which one fits — that inference is the part people miss.

    Nothing here is autonomous. It asked, something ran, an answer came back — then it stopped.

    4 · Structure of a tool

    Stable

    The description is the prompt

    A tool is four things: a name, a description, the shape of its arguments, and what comes back.

    The description is the one that matters. It is not documentation for you — it is the text the model reads when it decides whether your tool is the right one.

    Same instinct as few shots. Write it badly and the model quietly ignores your tool forever.

    5.2 · Four habits
    
      
    
        
    
        Shaky
      
    
    
    

    
    
      
    Ask in a way that does not hand it the answer.
    
      
    
        
    
          
    01 · don’t lead
    
          
    “It’s the cache, right?”
    “What are the three most likely causes, with the evidence for each?”
    
        
    
        
    
          
    02 · ask for the counter-case
    
          
    “What would make this the wrong approach?” It cannot agree with you and answer that at the same time.
    
        
    
        
    
          
    03 · make it show its work
    
          
    “Quote the lines you based that on.” Invented reasoning collapses the moment it has to cite something.
    
        
    
        
    
          
    04 · give it an out
    
          
    “Say you don’t know if you’re not sure.” Without permission to be uncertain, it will invent something confident.
    
        
    
      
    
    
    

    
    
      
    Not “is this good?”but “what would a reviewer flag?”
